# 简历项目描述与岗位映射

## 推荐项目名

**1Cat Agent Runtime｜可恢复、可观测的多 Agent 运行平台**

技术栈：Python、FastAPI、SQLAlchemy、PostgreSQL、Docker Compose、React/TypeScript、
Hermes Agent、MCP、OpenTelemetry、Jaeger、Prometheus、Grafana、DeepSeek API。

## 简历正文（推荐三条）

- 设计并实现持久化 Agent Runtime，统一管理 `queued → accepted → running → 终态` 生命周期，
  以不可覆盖 Attempt、30 秒 Lease、10 秒 Heartbeat 和 Fencing Token 支持故障恢复与旧 Worker
  写回隔离；完成 4 Worker × 20 Run 本机并发验收，重复有效执行为 0。
- 构建 PMA、BGA、MO 三岗位 Hermes + MCP 工具调用链，经本地 Model Gateway 安全接入
  DeepSeek；实现九阶段 Marketing Case 状态机，以 4 个 Commitment、2 个 Handoff、6 个
  Approval 串联 MO 规划、PMA Fact/Claim、BGA Campaign/Content、模拟发布、反馈与 MO 复盘。
- 将任务、协作、对象、决策、异常、Daily、Agent 配置和运行诊断统一为服务端事实页面；实现
  MO/PMA/BGA 持久化 Agent 对话、对象版本谱系与四层历史，并为模型参数、岗位六件套、Skill、
  工具权限和 Prompt 建立草稿/校验/发布/回滚链，使每个工作流或聊天 Run 固化 Profile
  version、SHA-256 hash 与不可变配置快照。
- 接入 OpenTelemetry、Jaeger、Prometheus 和 Grafana，贯通 API、Worker、Hermes 与 MCP 的
  Trace/Metric/结构化日志/状态时间线；通过 Worker kill、PostgreSQL 短暂中断、Hermes 超时和
  取消演练验证安全恢复及 `unknown/unsafe` 语义，并完成真实 Case 跨系统联查 13/13。

## 更短版本

- 实现带 Attempt/Lease/Heartbeat/Fencing 的持久化 Agent Runtime；4 Worker × 20 Run 本机
  并发验收无重复有效执行，并覆盖 Worker kill、断库恢复、超时和取消竞态。
- 打通 DeepSeek + Hermes + MCP 三岗位真实 Agent 链路并接入 OTel/Jaeger/Prometheus/Grafana，
  支持从 Run ID 追踪到执行轨迹、指标、日志和数据库状态迁移。

## 与 AI Agent 系统平台实习岗位的对应关系

| 岗位职责 | 项目证据 | 面试时怎么说 |
|---|---|---|
| Runtime 生命周期 | Run 状态机、Attempt 历史、取消与终态 | 状态迁移集中在统一服务，非法迁移失败并写审计 |
| 上下文与持久化 | PostgreSQL 保存 Run/Attempt/Timeline/Trace Context | 刷新或 Worker 重启后仍以服务端事实恢复 |
| 配置与上下文复现 | 版本化 Agent Profile、已发布 bundle、Run 配置快照 | 草稿不影响新 Run；历史 Run 可解释当时的 Prompt、Skill 和权限 |
| Tool/Plugin 调用 | Organization MCP、岗位白名单、Schema、上下文检查 | 已实现静态受限工具框架；动态注册与沙箱是后续项 |
| Agent 编排 | 九阶段 Case 状态机、服务端 `next_actions`、人工门禁 | 完成固定营销流程编排；通用 DAG 尚未实现 |
| 多 Agent 协作 | 持久消息、Change Request、Handoff、chat Run、对象谱系 | Agent 不直接互调，以服务端 Case 与人类门禁传递上下文和责任 |
| 多 Agent 调度 | PostgreSQL `SKIP LOCKED`、4 Worker 并发 | 证明无重复有效执行，不宣称生产容量或严格公平 |
| 可观测性 | OTel、Jaeger、Prometheus、Grafana、结构化日志 | 可按 Run/Attempt/Trace/Correlation ID 交叉定位 |
| Docker/云原生 | 单主机 Compose、健康检查、网络与 Secret 隔离 | Compose 已实测；Kubernetes 仍在下一阶段 |
| 测试与排障 | 单测、Smoke、E2E、故障注入和机器证据 | 先保留失败事实，再用确定性演练防止回归 |

## 不要写进简历的表述

- “生产级高可用”“大规模分布式”“百万级任务”——没有对应证据。
- “实现完整插件市场/生产沙箱/通用 DAG/Kubernetes”——尚未完成。
- “自动完成营销目标/自动发布内容”——R0 明确保留人工发布和最终确认。
- “p95 8.013 秒达到性能目标”——这只是 20 条本机短任务的 claim 基线，不是生产 SLO。
- “实现了动态插件或生产沙箱”——当前 Profile 权限和静态 MCP 白名单不是动态插件市场或隔离沙箱。
