# Agent Runtime 5～8 分钟演示脚本

## 演示目标

用一条故事证明：三 Agent 不是互不相关的模型调用，而是在同一持久化 Marketing Case 中，
经人类门禁、Commitment、Handoff、候选对象和模拟回执形成可恢复、可观察的业务闭环。

录屏前执行 `./bin/1cat portfolio-check`。不要打开 `.env`、Secret 文件或显示 API Key。

## 0:00～0:40　定位和边界

打开 `http://127.0.0.1:8080/?view=workflow`。

> 这是我实现的三 Agent 媒体业务 Runtime。MO 负责规划和复盘，PMA 形成 Fact/Claim，
> BGA 形成 Campaign/Content，人类在关键节点确认。Case、Run、Attempt 和所有业务对象都在
> 服务端持久化；发布只是 simulated 回执，系统不登录真实平台、不接触真实 PII。

## 0:40～3:20　三 Agent 完整业务闭环

在“完整流程工作台”切换到已完成真实案例，或新建合成案例逐步演示：

```text
Brief
→ MO 规划 review
→ 人工确认计划
→ PMA fact + claim
→ 人工产品审核 + Handoff
→ BGA campaign + content
→ 人工内容审核
→ simulated 发布回执
→ 合成 Lead + SalesFeedback
→ MO 复盘 review
→ 人工确认 completed
```

打开右侧对象区，指出 4 个 Commitment、2 个 Handoff、6 个 Approval、候选版本、
ManualTask、`external_effect=false` 回执、Lead 和销售反馈均是服务端事实。刷新浏览器，Case 和
当前阶段仍能恢复。

若需要命令复现：

```bash
.venv/Scripts/python.exe scripts/marketing_workflow_demo.py --mode synthetic
.venv/Scripts/python.exe scripts/marketing_workflow_demo.py --mode real
```

真实模式会调用 DeepSeek 并产生费用。当前验收案例保留了一次“复盘缺少 review”历史：Case
先进入 blocked，人工选择安全重试后新增 Run 并完成，旧 Run 没有被覆盖。这是故障证据，
不是需要隐藏的脏数据。

## 3:20～4:20　Worker 崩溃恢复

展示已有 safe-recovery Run，或执行不调用模型的演练：

```bash
.venv/Scripts/python.exe scripts/runtime_failure_drill.py --scenario safe-recovery
```

> 第一个 Worker 在外部派发前消失，Lease 过期后旧 Attempt 标记 lost，新 Attempt 执行成功。
> 所有写回都匹配当前 Attempt 与 Lease Token，所以过期 Worker不能覆盖新结果。

## 4:20～5:10　`unknown` 安全边界

```bash
.venv/Scripts/python.exe scripts/runtime_failure_drill.py --scenario unknown-after-dispatch
```

> 外部派发后无法确认结果时，自动重试可能制造重复副作用，所以系统进入
> `unknown/unsafe`，只允许人工对账或取消。这是 Runtime 对不确定性的显式建模。

## 5:10～6:40　全链路可观测性

从 Case 的 Agent 阶段打开 Trace，然后展示：

- Jaeger：`http://127.0.0.1:16686`
- Grafana：`http://127.0.0.1:3000`
- Prometheus：`http://127.0.0.1:9090`

> API 创建 Run 时持久化 W3C Trace Context；Worker 恢复上下文并记录 claim、Attempt、
> Hermes 调用。MCP 独立调用使用 Span Link，不伪造父子关系。最终真实 Case 的 5 条保留
> 历史 Run 均能在 Jaeger 找到 API/Worker 主 Trace 和 MCP Link；Grafana v4 有 20 个面板，
> 其中 9 个属于 Marketing Workflow。跨系统验收 13/13 通过。

可重复核对：

```bash
.venv/Scripts/python.exe scripts/marketing_workflow_observability.py \
  --case-id case_26571297a8f9438e891d18fe77771f86 --log-since 3h
```

## 6:40～7:30　收束

> 我已证明三 Agent 完整 Case、人工门禁、安全重试、Worker 恢复、unknown 语义和
> Trace/Metric/Log/数据库联查。`completed` 只表示本次合成业务案例完成；发布没有真实副作用，
> 也不代表营销效果。动态插件、通用 DAG、Kubernetes、生产 SLO 与真实平台发布仍是后续项。

## 录屏验收清单

- 总时长 5～8 分钟，不出现 API Key、`.env` 或个人账号信息。
- 展示九阶段 Case、三 Agent 角色关系和至少两个人工门禁。
- 展示一次安全重试或两个不可覆盖 Attempt，并解释 Fencing。
- 展示 `unknown/unsafe`，说明为何不能自动重试。
- 打开一条 Case Trace 和 Grafana Marketing Workflow 区域。
- 结尾明确 simulated、无真实平台副作用、无业务效果声明。
