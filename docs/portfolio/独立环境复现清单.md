# 独立新环境复现清单

## 目的

验证项目不是“只在开发机上碰巧能跑”。独立环境必须是另一台机器、虚拟机，或至少是一个
从未运行过本项目的全新 Windows 用户环境。仅在当前目录重新启动容器不算独立复现。

## 环境信息记录

复现者在开始前填写：

```text
日期：
机器/虚拟机标识：
Windows 版本：
Docker Desktop 版本：
Docker Engine：Linux containers / 其他
Git Bash 版本：
Python 版本：
项目来源（提交或压缩包 SHA-256）：
复现者：
```

不要把 `.env`、`.runtime`、API Key 或现有 Docker volume 复制到新环境。

## 第一阶段：无模型基线

在 Git Bash 进入项目根目录：

```bash
./bin/1cat doctor
./bin/1cat init
./bin/1cat up
./bin/1cat status
./bin/1cat smoke
./bin/1cat e2e
```

验收：

- Runtime、PostgreSQL、Keycloak、MinIO、MCP、Workspace 和三个 Hermes Gateway 健康。
- Smoke 12 个步骤全部通过。
- Workspace E2E 10/10 通过。
- `http://127.0.0.1:8080/?view=tasks` 可登录、新建 Case，并且刷新后恢复同一服务端阶段。
- 协作中心可向 MO/PMA/BGA 创建持久化聊天，返回消息关联 chat Run 和已发布 Profile。
- Agent 配置可保存草稿、校验、发布，并在运行诊断中看到不可覆盖的 version/hash/snapshot。
- `?mode=prototype` 明确标注为界面原型，不显示服务端案例且不能作为验收证据。
- 刷新页面后服务端 Run 状态仍可恢复。

## 第二阶段：可靠性与观测

```bash
./bin/1cat observe up
.venv/Scripts/python.exe scripts/runtime_failure_drill.py --scenario all
.venv/Scripts/python.exe scripts/runtime_reliability_drill.py \
  --scenario all --run-count 20 --worker-count 4 --database-outage-seconds 6
./bin/1cat portfolio-check
```

验收：

- 故障恢复 2/2、综合可靠性 5/5。
- 并发重复有效执行为 0。
- 派发后不确定结果进入 `unknown/unsafe`，没有自动重试。
- Jaeger、Prometheus、Grafana 和 Runtime/UI 健康。
- `.runtime/evidence/week8-readiness-latest.json` 的 `passed` 为 `true`。

## 第三阶段：可选真实 DeepSeek 验收

真实模型会产生外部请求和可能的费用，只在复现者明确授权后执行：

```bash
./bin/1cat auth deepseek
./bin/1cat restart-agents
./bin/1cat model-test
.venv/Scripts/python.exe scripts/real_agent_demo.py --role pma
.venv/Scripts/python.exe scripts/real_agent_demo.py --role bga
.venv/Scripts/python.exe scripts/real_agent_demo.py --role mo
.venv/Scripts/python.exe scripts/marketing_workflow_demo.py --mode real
```

验收：完整 Case 为 9 阶段 `completed`，角色阶段覆盖 MO/PMA/BGA/MO，候选类型符合岗位白名单，
模拟回执 `external_effect=false`。不要把技术闭环误记为真实发布或营销效果。

最后按脚本输出的 Case ID 执行跨系统联查：

```bash
.venv/Scripts/python.exe scripts/marketing_workflow_observability.py --case-id <case_id> --log-since 3h
```
