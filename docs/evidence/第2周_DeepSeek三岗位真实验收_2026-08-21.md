## 本轮修正

- `object_create_candidate.kind` 改为精确枚举，并按岗位二次校验。
- 新增 `candidate_kinds_read`，让 Agent 可读取当前岗位的精确候选类型。
- Worker 明确禁止通过 `tool_search/get_prompt` 猜测参数；参数失败最多修正重试一次。
- `commitment_respond.action` 改为精确枚举；标准 Run 的最终 `submitted` 由 Worker 原子写入，Agent 不自行跨状态推进。
- 新增通用 `scripts/real_agent_demo.py`，用 `--role pma|bga|mo` 运行固定边界场景，并校验对象级证据。

修正后的三岗位日志均未命中以下已知错误：

```text
unsupported candidate kind
tool_search
Unknown prompt
unsupported commitment action
commitment_respond returned error
409 Conflict
```

## 可重复验收

在项目根目录的 Git Bash 中执行：

```bash
./bin/1cat status
./bin/1cat model-test
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe scripts/real_agent_demo.py --role pma
.venv/Scripts/python.exe scripts/real_agent_demo.py --role bga
.venv/Scripts/python.exe scripts/real_agent_demo.py --role mo
```

每条真实 Run 的最后一行必须同时满足：

- `runtime_status=evidence_accepted`
- `hermes_status=completed`
- `commitment_status=submitted`
- `human_confirmation_required=true`
- `candidate_count > 0`
- `candidate_kinds_authorized=true`

## 边界披露

本轮使用合成、无 PII 的业务输入，证明的是三岗位的真实模型调用、受控 MCP 写入、
状态持久化和人工确认边界。它不证明真实平台发布、真实客户数据处理、Shadow/UAT、
生产容量或高可用。Hermes 启动时仍可能报告容器内不可访问宿主 Docker daemon；当前
岗位禁用终端和 Docker 工具，该启动告警不影响本轮 Organization MCP 链路，但不应
被描述为生产级沙箱已完成。
