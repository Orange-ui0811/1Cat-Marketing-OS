# Runtime 故障恢复真实演练（2026-08-26）

## 结论

两条本机容器故障链路均通过。演练实际停止正式 Worker，启动专用 victim Worker，
使用 `docker kill` 中止容器，再由独立 recovery Worker 根据 Lease 和外部派发边界
决定恢复。业务输入完全合成，未调用 Hermes、DeepSeek、MCP 或内容平台。

## 同时验证的安全边界

- `RUNTIME_DRILL_ENABLED` 默认关闭，正常 Worker 不进入停顿点。
- 演练 Worker 只允许 claim 指定 `RUNTIME_CLAIM_RUN_ID`，不碰其他排队任务。
- 演练强制使用合成执行状态文件，不读取当前真实模型开关。
- `GET /v1/runs/{id}`、`/attempts` 和 `/v1/attempts/{id}` 均不返回 `lease_token`。
- 演练结束后专用容器已删除，正式 `runtime-worker` 已恢复运行。

可复现命令：

```bash
.venv/Scripts/python.exe scripts/runtime_failure_drill.py --scenario all
```

机器可读原始结果保存在 `.runtime/evidence/runtime-failure-drill-latest.json`；该目录不入库。
