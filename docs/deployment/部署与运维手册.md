# 1Cat Hermes OS R0 部署与运维手册

## 本机启动

1. 启动Docker Desktop。
2. 运行`./bin/1cat doctor`。
3. 运行`./bin/1cat init`生成本机Secret和Profile Bundle。
4. 运行`./bin/1cat up`。
5. 打开`http://localhost:8080`，使用`admin`和`.env`中的`INITIAL_ADMIN_PASSWORD`登录；共享部署首次使用后立即修改密码。

核心工作台不依赖模型即可运行。真实Agent需要额外执行`./bin/1cat auth codex`，按终端提示在浏览器完成设备授权，再执行`./bin/1cat restart-agents`。

## 安全边界

- 服务默认只绑定`127.0.0.1:8080`。
- `.env`与`.runtime`权限为当前用户可读，不能提交或打包。
- 平台主凭据不应配置到本系统。
- `profiles/dormant/SKL-BG-11`不得复制进BGA Profile。
- `unknown`运行结果必须人工对账，不能重用新幂等键自动重试。

## Linux部署

在目标架构机器解压对应`linux-arm64`或`linux-amd64`包。离线包内的Compose只引用本地镜像标签，不访问镜像仓库；安装程序会先校验镜像归档，再加载镜像、检查基线并初始化随机Secret：

```bash
./install.sh
./bin/1cat up
./bin/1cat smoke
```

目标机必须与部署包架构一致，并预装Docker Engine、Compose v2、Python 3和zstd。默认只监听`127.0.0.1:8080`；需要受控内网访问时，由技术Owner修改绑定地址并补充TLS、主机防火墙和访问审批。

API Key模式把Key写入`.runtime/secrets/model_api_key`，权限设为`600`，由Docker Secret挂载给Model Gateway。Secret不得写进`.env`、镜像、日志或测试证据。模型启动检查失败时保持失败关闭，不静默切换Provider或模型。

## 验证

```bash
./bin/1cat doctor
./bin/1cat test
./bin/1cat smoke
./bin/1cat e2e
./bin/1cat status
```

`smoke`使用合成数据验证Brief→PMA→BGA→人工发布任务→LeadStub→销售反馈→MO复盘，不执行真实发布，也不构成Shadow或UAT。`e2e`使用Playwright验证中文登录、主要导航、人工发布边界和无PII界面。

## 备份、恢复与升级

`./bin/1cat backup`生成PostgreSQL、Hermes和MinIO三部分备份及`SHA256SUMS`。恢复会覆盖当前数据，必须由具名技术Owner核对目标和备份目录后显式执行：

```bash
./bin/1cat restore .runtime/backups/1cat-YYYYMMDD-HHMMSS --confirm
```

恢复程序会校验hash、停止写入服务、恢复三部分数据、重新启动并自动执行Smoke Test。备份目录权限保持为当前用户独占；不要复制到未批准的共享位置。

升级前必须备份并保存当前平台部署包、镜像、Bundle Manifest、数据库迁移版本和`docs/gates/status.yaml`。先在独立数据卷验证升级和回滚，再切换受控环境。失败时停止新版本，重新加载旧部署包镜像并恢复匹配的数据库、Hermes与MinIO备份；不得只回滚Profile而保留不兼容数据。

## 已知保留门

- `./bin/1cat auth codex`需要用户本人完成设备授权；未授权前真实模型Run保持关闭。
- BG-07～10源ZIP权属与hash尚待业务方提供和验收，激活状态为`pending`。
- Trivy扫描仍存在Critical/High项；进入真实Shadow前必须完成可达性分析、修复或VEX审批。
- 真实Owner签署、Shadow、UAT、DEC-08和G4决定均不能由合成测试替代。
