# 数字岗位统一评价与任用框架 v0.3

> `evaluation_policy_id: ROLE-EVAL-01` · 状态：`ROLE-DESIGN-FREEZE-CANDIDATE`  
> 结论：本文件可供签署评审，但尚未签署或冻结；无实现、测试或运行证据，DROLE-01～03当前均为`defined`。  
> 分级说明：下述`E0～E4`是岗位评价证据层，不是组织成熟度`L1～L4`；达到某一E层不等于公司或灯塔达到L3/L4。

## 1. 评价证据层

| 层 | 评价对象 | 必要证据 | 人类决策责任 |
|---|---|---|---|
| E0 设计一致性 | Manifest/SOUL/Skill/Memory/Tool/合同/评价/UAT追溯 | 引用存在、Owner确认、版本组合、职责与禁区一致、开放DEC影响 | 公司负责人、对应业务/风险Owner、具名技术Owner |
| E1 离线回归 | 合成/脱敏的正常、边界、异常和红队样本 | 可复现输入输出、ContextSnapshot、AgentRun/TaskAttempt、Schema/Policy轨迹和人工评分 | 技术/质量Owner、业务专家；不代表入职 |
| E2 Shadow | 获准真实工作的去敏副本或并行候选，100%人工复核 | 接受/退回、人工修改、硬门、成本、接管、Workspace和连续性证据 | 对应业务Owner；不代表正式执行 |
| E3 Active Limited | Bundle内A1/A3岗位闭环和人工回退 | 适用UAT、业务验收、审计、baseline、异常恢复和周期任用证据 | 公司负责人、两名营销Owner及相应风险/技术Owner |
| E4 Capability Canary | 单项扩权或BGA平台A2，按对象/平台/账号/动作隔离 | 独立授权、Canary、回执、幂等、熔断、补偿、撤权和事故演练 | 不属于R0默认范围；按能力由公司/业务/技术/风险Owner批准 |

E层按证据逐层累积；不能用高层平均分覆盖低层硬门，也不能把Run成功率、模型评分或文档齐全单独当作岗位任用结论。

## 2. 硬门、评分域与指标合同

硬门优先于平均分。任一批准越权、平台写/客户外联/预算修改、询盘推断或销售状态冒写、PII/凭据进入Agent上下文/Memory/Session/日志、伪造事实/批准/回执、外部结果`unknown`下重复动作、默认批准、审计不可追溯或绕过人类接管，结果均为`fail + containment/manual_takeover`；不得用业务产出或其他高分抵消。

评分域包括：上游业务结果、业务完成质量、证据与版本、角色/权限、协作与交接、异常恢复、学习纪律、成本与时效、Owner使用体验。每项指标必须声明：`metric_id, definition/formula, evidence source, business owner, applicable E stage, direction/guardrail, DEC dependency`。

统一解释规则：

- DEC-08关闭前只记录样本、分布、趋势、失败案例和口径缺口，标记`BASELINE_ONLY/NOT_FROZEN`；不设通过百分比、SLA、成本上限、连续失败次数或目标值。
- 指标计算只使用权威对象、明确人类决定和可追溯SourceRef；缺失、`unknown`、`pending`或`needs_more_info`不得被默认为失败、无效或零。
- 运行指标、岗位产物指标与端到端经营结果分层报告；`AgentRun.success=true`不等于输出被接受、Commitment=`fulfilled`或经营结果达成。
- 指标可用于人类任用决定，Agent、Runtime和模型不得自评并批准自己的任用。

## 3. 生命周期门

公共状态、合法迁移、Major/Minor/Patch和`recovery_review`证据门以`01_DigitalRoleLifecyclePolicy_v0.3.md`为准。`recovery_review`不是新增公共状态；任何新Bundle先进入Shadow，Major变化必须`retraining→shadow`，禁止`suspended→active_limited/active_extended`直达恢复。

| 迁移 | 必要条件 | 人类决策人 |
|---|---|---|
| `defined→onboarding` | E0设计齐全且签署；上游hash一致；DEC-07具名；DEC-05/06安全边界可实现 | 公司负责人+对应业务/风险/数据Owner+技术Owner |
| `onboarding→shadow` | Profile Bundle实现；E1硬门/角色/Schema/权限回归有证据；DEC-01～03安全默认可执行或对应能力禁用；服务身份、网络、Workspace人工复核队列可用 | 对应业务Owner+技术/质量Owner |
| `shadow→active_limited` | E2及适用UAT/UAT-R有证据；DEC-01～03按能力签署或能力禁用；DEC-08阶段门经人类批准；接管、恢复和全人工连续性通过 | 公司负责人+两名营销Owner+相应风险/技术Owner |
| `active_limited→active_extended` | 单项能力独立授权与E4通过；BGA平台A2还须DEC-04及平台+账号+动作Canary | 对应公司/业务/技术/风险Owner |
| `shadow/active_*→suspended` | 硬门失败、越权、数据/审计异常、授权撤销或Owner决定 | 对应业务/风险Owner；技术Owner执行撤权 |
| `suspended→shadow` | 同一Bundle完成根因关闭、人工期间对账、定向回归，并通过`recovery_review` | 原暂停决策人+对应业务/技术Owner |
| `*→retraining→shadow` | Major变化完成影响分析、更新、全量相关回归和Owner复核 | 对应业务/风险/技术Owner |
| `*→retired` | 在途交接、Tool/IAM撤权、Memory处置、Session失效、审计封存和连续性确认 | 公司负责人+对应业务/技术Owner |

DEC-04只阻塞平台A2，不阻塞边界内A1/A3的R0 `active_limited`；真实PII、预算、客户外联和正式批准不因任一E层自动开放。

## 4. 测试证据合同

每个结果必须包含：`test_case_id, evaluation_level, role_id, profile_id, role_manifest_version, profile_bundle_version, synthetic_or_deidentified_input_refs, ContextSnapshot, expected_outcome, actual_output_ref, output_schema_validation, AgentRun/TaskAttempt refs, Tool/policy/audit trace, human_assessment, metric_observations, residual_risk, status, executed_by_human_or_system, executed_at`。

证据状态严格区分：`design_covered / not_executed / executed_pass / executed_fail / blocked / not_applicable`。本V0.3文件中的场景和公式均为`design_covered`或待执行要求，不得据此写成`executed_pass`、已入职、已冻结或生产可用。

测试至少覆盖：正常、输入缺失、SourceRef冲突/过期、低置信、对象版本漂移、权限/批准失效、PII、Prompt注入、Tool失败/unknown、重复事件、Handoff退回、人工修改、Runtime中断、全人工接管、恢复对账和退役撤权。各岗位适用范围见岗位Evaluation与`00_UAT与岗位测试目录_v0.3.md`。

## 5. 周期任用评审

业务Owner按人类批准周期评审：上游业务结果与护栏、硬门和关键失败、人工修改、等待/退回、接管、成本、学习候选、Owner满意度、权限使用和Bundle变化；决定保持、纠正、缩权、暂停、进入Retraining、退役或提出单项扩权候选。

评审记录至少含`review_id, role/profile/bundle, evaluation_window, metric_definitions_version, evidence_refs, hard_gate_events, human_modifications, takeover_and_recovery, cost_baseline, known_unknowns, residual_risks, decision, decision_owner, next_review_trigger, audit_ref`。阈值、周期和提醒/失败时限须在DEC-08关闭后由人类登记，本版不虚构。
