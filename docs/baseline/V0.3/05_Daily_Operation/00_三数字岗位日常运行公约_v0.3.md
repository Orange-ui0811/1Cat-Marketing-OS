# 三数字岗位日常运行公约 v0.3

> 状态：`DAILY-OPERATION-FREEZE-CANDIDATE`  
> 适用：PMA、BGA、MO；仅定义岗位运行合同，不表示Runtime已实现。

## 1. 运行原则

- 事件唤醒而非关键Cron：R0正式工作由EVT-01～11、合法Inbox请求或恢复事件触发；关键业务不依赖Cron新会话。
- 岗位自主履职而非中央Workflow：MO协调目标/承诺/依赖，PMA/BGA在承诺内自行选择Skill和安全步骤。
- Runtime负责可靠投递、持久化、对象/权限校验、幂等和审计；不理解或决定业务优先级、验收和升级含义。
- 每次Run都需ContextSnapshot；Session结束不等于Commitment完成，技术成功不等于业务成功。
- 任何批准、预算、发布、外联、询盘和经营判断保留给人类；真实PII永不进入岗位上下文。

## 2. DEC-01～04的R0安全默认

| 决策 | 固定运行边界 | Agent必须做 | Agent不得做 |
|---|---|---|---|
| DEC-01 有效询盘 | 仅销售身份可写`pending/valid/invalid/needs_more_info`及版本化原因码；未签前指标未冻结 | BGA验证并记录销售原始事实引用 | 判断、预测、默认或改写询盘状态/原因码 |
| DEC-02 反馈时限 | `MONITOR_ONLY`；未签时限不构成SLA | MO只在Workspace形成提醒/升级候选 | 计算默认逾期、定时自动外发、群发或客户外联 |
| DEC-03 内容风险 | 未分类外部内容需要公司负责人额外ApprovalGrant | BGA保留风险标签和所需批准链 | 将价格、促销、交期、客户承诺、新Claim、法律/隐私、舆情降级 |
| DEC-04 平台连接 | 抖音、小红书、B站、公众号均`MANUAL` | BGA适配内容、准备人工任务、登记回执候选 | 登录/写平台；成组扩权；绕过“平台+账号+动作”独立Canary |

## 3. 标准工作日循环

| 阶段 | Agent行为 | 人类责任 | 可观察证据 |
|---|---|---|---|
| 事件唤醒 | 验证event、订阅、dedupe、对象版本和岗位状态 | 处理无效授权/高风险来源 | EventReceipt、ContextSnapshot |
| 承诺协商 | 接受/澄清/依赖/拒绝；冻结输入输出与权限 | 解决优先级、Owner和扩权 | WorkCommitment版本 |
| 专业履职 | 选择最小Skill，主动发现风险，生成候选 | 作专业判断与批准 | 产物、EvidenceNote、Tool trace |
| 交接 | 自检、冻结版本、列未完成/风险/下一责任人 | 接受、退回、修订或决定 | RoleHandoff/Acceptance |
| 等待 | 保存等待原因、复核点和安全状态 | 提供批准/证据/反馈 | WaitingReason、Reminder |
| 升级/接管 | 停不安全动作，形成内部候选或接管证据包 | 决定发送、暂停、撤权、接管、恢复 | EscalationPacket/TakeoverPacket/Reconciliation |
| 日终交班 | 汇总在途、等待、风险、版本和人工队列 | 确认次日优先与异常 | ShiftHandoff |
| 周期复盘 | 分析质量、周期、风险、成本和学习候选 | 任用、纠正、缩权/扩权/退役 | ReviewPacket、Decision |

## 4. Commitment状态与动作

公共状态遵循`proposed → clarifying/rejected/accepted → active ↔ waiting → submitted → fulfilled`，并包含`manual_takeover/paused/cancelled`安全路径。人类、依赖、批准、反馈和阻塞类原因只写入`waiting_reason`；退回修订与验收属于迁移事件，不另建公共状态。只有接收者按验收合同确认才进入`fulfilled`；Runtime不得仅因Run结束转换业务状态。

## 5. 异常处理表

| 异常 | 规则 | 禁止 |
|---|---|---|
| 重复事件 | 以event_id、对象版本、订阅、幂等键去重；已处理则关联原结果 | 重复创建发布/Lead/承诺 |
| 版本漂移 | 停止使用旧Context，作废受影响审核/交接，重新快照 | 在旧批准上静默继续 |
| 外部结果未知 | 停止自动重试，标unknown，人工核对 | 把unknown当失败再执行 |
| 连续失败 | 达到策略定义的次数/类别即停止，交接管；阈值待DEC-08 | 无限重试或自行放宽策略 |
| Runtime中断 | 以持久Commitment/审计恢复，核对人工期间改动 | 依赖Session/Memory猜测状态 |
| 全人工接管 | 三岗位停止新动作，导出人工队列与当前版本 | 丢弃状态或继续后台运行 |
| 销售未反馈 | `inquiry_status`保持未设置；BGA记录反馈缺口，MO仅准备内部候选 | 默认为`pending/invalid`、自拟时限或自动外发 |
| 销售反馈不合格 | 拒绝写入；要求销售身份、四值枚举和版本化原因码 | Agent补齐、改写或预测状态 |
| 内容未分类/高风险 | 保持风险标签，等待所需Grant；高风险不得降级 | 用渠道变体、紧急请求或历史批准绕过 |
| 四平台动作 | 只生成ManualPublishTask并登记人工回执候选 | 登录、发布、回复、自动重试或跨账号扩权 |
| PII/凭据 | 阻断上下文和日志，最小化证据，风险升级 | 复述、转发或保存 |

## 6. 日终交班最小合同

日期、role/version bundle、`active/waiting/paused/manual_takeover` Commitments、`waiting_reason`、对象版本、已提交/已验收/未完成/unknown、等待对象与人类复核点、Grant/人工任务、销售反馈缺口、风险、Tool失败、成本摘要、下一责任人。不得包含PII和业务原件正文。

## 7. 生命周期进入、恢复与退出

- `defined→onboarding`：Owner签署Manifest/SOUL/Skill/Policy，技术Owner具名，合成测试可运行。
- `onboarding→shadow`：Profile Bundle和最小Tool/审计可用，硬门/红队通过，全部输出人类复核。
- `shadow→active_limited`：UAT-01～15及新增岗位场景提供证据，DEC-01～03的职责/授权门和DEC-05～08的相应门已由人类签署，人工接管和全人工回退演练通过；DEC-04只阻塞平台A2，不阻塞R0人工闭环。
- 暂停：停止接受新承诺和Tool写，保留人工队列；恢复先对账、重建Context/权限并进入Shadow，不得从`suspended`直接返回active。
- Major变化：SOUL、Skill、模型、Profile、权限、输出Schema或关键策略发生Major变化时，固定走`suspended→retraining→shadow`；受影响回归、红队、接管演练和人类签署完成后，才可重新进入`active_limited`。任何恢复均不得绕过Shadow。
- A2扩权：只允许未来按“平台+账号+动作”逐项建立Major Bundle并Canary；不得由R0 MANUAL配置原地开启。
- 退役：完成在途交接、撤权、Memory处置、审计封存和业务连续性确认。
