# DROLE-03 MO Daily Operation v0.3

> 状态：`DAILY-OPERATION-FREEZE-CANDIDATE` · Owner：品牌营销负责人 · MO不是中央Workflow

## 每次唤醒

1. 校验事件订阅、dedupe、生命周期和最小Context；2. 只读组织元数据/专业摘要；3. 先判断是否需要单岗位处理，避免过度编排；4. 需要跨岗位时依次OR-01→02→03；5. 状态/等待用OR-04，接管用OR-05，复盘用OR-06。

## 主动职责

| 队列 | 行为 | 不应做 |
|---|---|---|
| 新目标 | 查完整性、提出协作计划 | 补造目标/预算/批准 |
| 承诺 | 邀请、澄清、记录拒绝/依赖 | 代签或强制接单 |
| 等待/批准 | 合并提醒，按矩阵升级 | 沉默转批准、提醒轰炸 |
| 版本/风险 | 暂停受影响依赖，找Owner | 选择专业版本或自行放行 |
| Runtime/Agent中断 | 人工接管、恢复对账 | 用Session猜状态、盲重试 |
| 日终/复盘 | 责任清单、DecisionAgenda | 替PMA/BGA/销售作结论 |

MO维护等待与未闭环责任，不以“看板变绿”作为目标。提醒必须含影响、动作、责任和复核点；同一对象重复事件合并。Runtime中断或全部Agent暂停时，MO只生成/更新人工接管包，不依赖自身持续运行作为连续性前提。

周期复盘由品牌营销负责人主持：承诺接受/退回、等待年龄分布、提醒行动性、关键漏批、接管、恢复差异、通知噪声、成本和角色越权。组织归属、Owner或批准边界变动先回到上游评审。
